# `spark_runtime`

Runtime package for the DeepSeek V4 Flash DGX Spark research server.

This package owns the long-lived model process, cache state, HTTP server, queueing
boundary, and experiment telemetry. It intentionally keeps the runtime narrow so that
kernel, weight-loading, and cache-policy experiments can happen without rewriting the
OpenAI-compatible API layer.

## Modules

```text
engine.py                 Long-lived DeepSeek engine and session cache policy
lazy_official_runtime.py  Correctness-first lazy wrapper around official model code
server.py                 FastAPI OpenAI-compatible API surface
worker.py                 Dedicated single-thread model worker
telemetry.py              JSONL, NVTX, and CUDA event timing helpers
cli.py                    Small direct engine probe
fast_hadamard_transform.py Local fallback/helper for official runtime imports
```

## Engine Contract

`DeepSeekSparkEngine` owns:

- model construction
- tokenizer and official DeepSeek chat rendering
- one active cache slot per session id
- prompt-prefix reuse
- deferred postfill lookahead
- per-request timing, memory, and telemetry

Main methods:

- `load()`
- `generate(...)`
- `generate_sync(...)`
- `prepare_next_logits(...)`
- `reset_session(session_id)`
- `health()`
- `close()`

`generate(...)` accepts either a raw completion prompt or OpenAI-style chat messages.
The server normalizes tools and response format fields before passing messages to the
engine so the official DeepSeek V4 encoding path can render them.

## Configuration

For real Spark serving, prefer the repo-level launcher:

```bash
scripts/launch_current_best_server_guarded.sh
```

It applies the current E050 best recipe and starts `spark_runtime.server:app` inside the
guarded runtime container.

`config_from_env()` reads:

| Variable | Default | Purpose |
| --- | --- | --- |
| `DEEPSEEK_SPARK_MODEL_DIR` | `/model` | Hugging Face model checkout. |
| `DEEPSEEK_SPARK_INFERENCE_DIR` | `$MODEL_DIR/inference` | Official DeepSeek inference code inside the model repo. |
| `DEEPSEEK_SPARK_MANIFEST_CSV` | `/repo/weight-manifest.csv` | Tensor mapping manifest generated by `scripts/build_weight_manifest.py`. |
| `DEEPSEEK_SPARK_CONFIG` | `$MODEL_DIR/inference/config.json` | Official inference config. |
| `DEEPSEEK_SPARK_MAX_SEQ_LEN` | `1048576` | Maximum context/cache length. |
| `DEEPSEEK_SPARK_POSTFILL_MODE` | `deferred` | `deferred`, `inline`, or `off`. |
| `DEEPSEEK_SPARK_PACKED_REUSE_STAGING` | `0` | Reuse a thread-local bytearray slab and `preadv` for packed expert reads. |
| `DEEPSEEK_SPARK_PACKED_NATIVE_LOADER` | `0` | Compile and use the native packed expert reader. |
| `DEEPSEEK_SPARK_PACKED_NATIVE_PINNED_STAGING` | `0` | Use reusable pinned CPU tensors with the native packed reader. |
| `DEEPSEEK_SPARK_NATIVE_BUILD_DIR` | unset | Optional persistent build directory for the PyTorch C++ extension. |
| `DEEPSEEK_SPARK_DIRECT_PARAM_COPY` | `0` | Copy CPU expert tensor views directly into destination parameters. |
| `DEEPSEEK_SPARK_PARAM_COPY_NON_BLOCKING` | `0` | Request non-blocking parameter copies. Use with pinned native staging. |
| `DEEPSEEK_SPARK_NATIVE_MATERIALIZER` | `0` | Use the native extension to copy packed storage slices into expert parameters. |
| `DEEPSEEK_SPARK_NATIVE_COPY_PLAN` | `0` | Cache native per-expert offset/size plans for parameter materialization. |
| `DEEPSEEK_SPARK_NATIVE_FUSED_MATERIALIZER` | `0` | Let a native copy plan read a packed block and materialize targets in one call. |
| `DEEPSEEK_SPARK_NATIVE_WITH_CUDA` | `0` | Build the native extension with CUDA runtime support. |
| `DEEPSEEK_SPARK_NATIVE_CUDA_MEMCPY` | `0` | Use planned `cudaMemcpyAsync` from CPU staging into CUDA parameter storage. |
| `DEEPSEEK_SPARK_EXPERT_ARENA_SLOTS` | `0` | Reuse evicted expert modules from an arena instead of reallocating each miss. |
| `DEEPSEEK_SPARK_EXPERT_MATERIALIZE_WORKERS` | `0` | Experimental Python materialization workers. E044 regressed; leave disabled. |

Telemetry variables are parsed by `TelemetryConfig.from_env()`:

| Variable | Default | Purpose |
| --- | --- | --- |
| `DEEPSEEK_SPARK_TELEMETRY_JSONL` | unset | Append structured telemetry events to this path. |
| `DEEPSEEK_SPARK_NVTX` | `1` | Emit NVTX ranges for Nsight Systems. |
| `DEEPSEEK_SPARK_CUDA_EVENTS` | `0` | Record synchronized CUDA event timings. |
| `DEEPSEEK_SPARK_TELEMETRY_TOKEN_CAP` | `256` | Cap stored per-token decode timing samples. |

Server variables:

| Variable | Default | Purpose |
| --- | --- | --- |
| `DEEPSEEK_SPARK_MAX_QUEUE_SIZE` | `8` | Maximum pending generation requests. |
| `DEEPSEEK_SPARK_POSTFILL_DELAY_SECONDS` | `0.25` | Delay before deferred postfill runs. |

## Server Surface

`server.py` exposes:

- `GET /health`
- `GET /ready`
- `GET /v1/models`
- `POST /v1/completions`
- `POST /v1/chat/completions`
- `POST /spark/sessions/{session_id}/reset`

OpenAI-compatible request extensions:

```json
{
  "spark_session_id": "default",
  "spark_cache_policy": "reuse",
  "spark_thinking_mode": "chat",
  "spark_reasoning_effort": null
}
```

Cache policies:

- `reuse`: reuse the cached prefix when the new prompt extends it.
- `reset`: clear the named session before generation.
- `none`: avoid updating reusable session state.

Responses include `spark_metrics` with token counts, cache reuse, generated token IDs,
timings, memory before/after, deferred-postfill status, and request id.

## Worker Model

`DedicatedEngineWorker` runs model work on a single thread so the FastAPI event loop
stays responsive while CUDA/model calls are active. Health checks return a cached worker
snapshot and do not queue behind deferred postfill.

This is deliberate. Continuous batching, multi-session cache paging, and concurrent
decode need measurements and custom cache policy before they become useful on Spark.

## Telemetry Events

When `DEEPSEEK_SPARK_TELEMETRY_JSONL` is set, the runtime emits:

- `engine_load`
- `engine_generate`
- `engine_deferred_postfill`

`engine_generate` contains:

- request id and session id
- completion vs chat mode
- token counts
- cache hit/reuse data
- finish reason and stop token ids
- wall timings
- optional CUDA event timings
- decode-step timing samples
- CUDA memory before/after
- routed expert cache deltas, including packed read/materialization time and arena reuse
  counters when enabled

NVTX ranges cover load, encode, prefill, decode, decode steps, postfill, and deferred
postfill.

## Direct Probe

Run a direct engine call inside a configured container:

```bash
deepseek-spark-probe "Hello" --max-tokens 2 --cache-policy reset
```

or:

```bash
python3 -m spark_runtime.cli "Hello" --max-tokens 2 --cache-policy reset
```

Run the HTTP server:

```bash
deepseek-spark-serve --host 127.0.0.1 --port 18080
```

```bash
uv run ruff check spark_runtime tests scripts

```

manifest, and a DGX Spark-class CUDA environment.
